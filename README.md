# متجر الإمدادات الذكية الحديثة — المتجر الرقمي

متجر إلكتروني لمؤسسة **الإمدادات الذكية الحديثة للدعاية والإعلان** يخدم الأفراد والشركات والجهات الحكومية، بهوية المتجر الأصلية (الشعار، الألوان، خط Shamel، الطابع البصري)، ومربوط بـ **Firebase** (مشروع `edadatstor`).

- **واجهة المتجر** `index.html`: المنتجات والتصنيفات والأسعار بالريال السعودي (رمز ⃁)، السلة وإتمام الطلب، طلبات عروض الأسعار للشركات والمشاريع والمنتجات المخصصة، رفع ملفات التصميم، حسابات العملاء، تتبع الطلبات، والصفحات التعريفية والقانونية.
- **لوحة التحكم** `admin.html`: الطلبات وعروض الأسعار، المنتجات، الأسعار واعتمادها، العروض والخصومات، الأقسام، معرض الأعمال، العملاء، الرسائل، محتوى الصفحات، الإعدادات (ومنها سلايدر الرئيسية).
- لا يحتاج خادمًا: Firebase Hosting أو GitHub Pages أو Vercel. ملفات `dist/` مبنية ومرفوعة.

## ربط مشروع Firebase `edadatstor` (خطوات تنفّذها الإدارة مرة واحدة)

| الخطوة | المسار في Firebase Console | ما تختاره |
|---|---|---|
| 1. تطبيق ويب | ⚙️ Project settings ← General ← Your apps ← `</>` | اسم `emdad-store` ← Register app ← انسخ `firebaseConfig` |
| 2. Firestore | Build ← Firestore Database ← Create database | موقع قريب من السعودية (مثل `me-central2` الدمام إن ظهر) — **لا يمكن تغييره لاحقًا** ← Production mode |
| 3. Authentication | Build ← Authentication ← Get started ← Sign-in method | فعّل **Email/Password** و**Anonymous** (لرفع ملفات الزوار) |
| 4. Storage *(يتطلب Blaze)* | Build ← Storage ← Get started | نفس موقع Firestore |
| 5. القواعد | Firestore ← Rules / Storage ← Rules | الصق محتوى `firestore.rules` و`storage.rules` ← Publish (أو `npm run deploy:rules`) |
| 6. أول مشرف | Authentication ← Users ← Add user، ثم Firestore ← مجموعة `admin_users` ← مستند معرّفه = **User UID** وحقل `email` | لا يمكن لأي حساب منح نفسه الصلاحية من الموقع |

بعد الخطوة 1 ضع القيم في `.env` (انسخ `.env.example`):
```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=edadatstor
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```
ثم:
```bash
npm install
```
```bash
npm run build
```
يولّد `npm run build` الملف `firebase-config.js` من `.env` (قيم إعداد الويب ليست سرية؛ الحماية بقواعد الأمان). **لا تضع أي مفتاح خدمة (Service Account) في الواجهة.**

ادخل `admin.html` بحساب المشرف واضغط **«استيراد البيانات الأولية»** (أو **الإعدادات ← ترقية الكتالوج** إن كانت هناك بيانات سابقة؛ تضيف الناقص دون استبدال أي قيمة).

### Cloud Functions (اختياري — يتطلب Blaze وموافقة الإدارة)
`functions/index.js` يعيد حساب أسعار وإجمالي كل طلب شراء من جهة الخادم ويكتب نتيجة التحقق على الطلب. النشر: `npm run deploy:functions`. بدونه تعرض لوحة التحكم مطابقة الطلب مع الأسعار الحالية، ولا يُعتمد أي طلب دون مراجعة المشرف.

## بنية قاعدة البيانات (Firestore)

| المجموعة | المحتوى |
|---|---|
| `products` | الاسم، الوصف، الصور، التصنيف، `mode` (buy/quote)، `price` و`compareAt` بالريال، `priceApproved`، الوحدة، المخزون، الحد الأدنى، مدة التنفيذ، المواصفات، خيارات التخصيص بفروق الأسعار، الإضافات، رفع الملفات، مميز، الشعبية، `active` |
| `categories` | الأقسام: الاسم، الوصف، الصورة، الخدمات، الاستخدامات، المميزات |
| `promotions` | العروض: نسبة/مبلغ، النطاق (الكل/أقسام/منتجات)، تاريخ البداية والنهاية، شارة |
| `orders` | طلبات الشراء: البنود والأسعار والإجماليات (⃁)، الاستلام/التوصيل، طريقة الدفع، الحالة، السجل |
| `quotes` | طلبات عروض الأسعار (شركات/مشاريع/منتجات مخصصة) مع المرفقات وقيمة العرض |
| `tracking` | حالة الطلب العامة للتتبع برقم الطلب + آخر 4 أرقام من الجوال (بدون بيانات شخصية) |
| `customers` | ملف العميل: الاسم، الجوال، الجهة، الرقم الضريبي، العناوين، المفضلة |
| `messages` | رسائل «اتصل بنا» وبلاغات «الإبلاغ عن مشكلة» |
| `pages` | محتوى الصفحات التعريفية والقانونية (قابل للتعديل والاعتماد) |
| `settings/store` | بيانات المؤسسة والتواصل والضريبة وطرق الدفع والتوصيل وساعات العمل والسلايدر والصيانة |
| `admin_users` | المشرفون |
| `portfolio` | معرض الأعمال |

**الصلاحيات** (`firestore.rules`، مغطاة بـ 11 اختبارًا آليًا): الزائر يقرأ المنشور فقط وينشئ طلبات بصيغة محددة؛ العميل يقرأ ويعدّل ملفه فقط ويرى طلباته فقط؛ لا أحد غير المشرف يعدّل المنتجات أو الأسعار أو الإعدادات؛ ملفات العملاء في Storage لا يقرؤها إلا المشرف.

## التطوير والاختبار

```bash
npm run dev
```
```bash
npm test
```
`npm test` يشغّل محاكيات Firebase ويختبر قواعد الأمان (يتطلب Java). لتجربة المتجر كاملًا محليًا: `npm run emulators` وضع `projectId: 'demo-emdad'` في `firebase-config.js` (أي مشروع يبدأ بـ `demo-` يتصل بالمحاكيات).

| المسار | المحتوى |
|---|---|
| `src/app/` | واجهة المتجر: `core` (التنقل والقوائم والتذييل)، `home`، `shop`، `cart`، `account`، `pages`، `uploads` |
| `src/admin/` | لوحة التحكم |
| `src/lib/` | التسعير (`pricing.js`)، طبقة البيانات (`api.js`)، البيانات الأولية (`seed*.js`) |
| `firestore.rules` · `storage.rules` · `functions/` | الأمان والتحقق من جهة الخادم |
| `assets/fonts/` | خط Shamel + خط رمز الريال (SIL OFL 1.1) |
| `docs/REPORT.md` | تقرير التسليم وجدول الصفحات والبيانات المنتظرة |
